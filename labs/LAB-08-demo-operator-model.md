# LAB-08 — Training the demo operator model for ALICE on CPU (op12k)

**Date:** 2026-10-07 · **Host:** this 4-vCPU cloud VM, no GPU (env=vm) · **Status:** complete. Training finished 2026-10-08 05:07 UTC at step 12,000; §6c holds the final-checkpoint results.
**Rule A:** no throughput, tokens/s or wall-clock figure in this note is a product number; training speed is mentioned only to explain the budget. **Rule B:** every digest, count and rate below is copied from a file under `labs/logs/opmodel/` or `model/demo-operator/`.

## 1. Why
The QEMU demo (LAB-04, LAB-06) boots the M7 gate model, a 14M-parameter ternary model trained on children's stories; its receipts are exact but its answers are "Once upon a time, there was a little girl named Lily". The request was a demo model that gives much more impressive responses. A fine-tune of the 2B needs a GPU this machine does not have (the Kaggle notebook in `model/kaggle/` is that path). What *can* be trained here in a working day is a small ternary **operator model** whose value is behaviour, not trivia: it answers in ALICE's voice, delegates arithmetic to `CALC`, reads declared tables with `LOOKUP`, refuses to invent records, and describes the machine it runs on. Everything it learns about tools is produced by an exact oracle in the gateway's own text format, so the training signal cannot be wrong.

## 3. Model and recipe (`model/demo-operator/op12k.json`)
Llama-family decoder matching the engine: RMSNorm, RoPE θ=10000, GQA 6 heads / 2 kv heads, SwiGLU, BitNet SubLN, tied embeddings, all 7 projections `BitLinear` ternary QAT with per-token int8 activations (tinybit `model.py`, engine-parity contract in its README). hidden 384, intermediate 1024, 8 layers, vocab 12,288, ctx 512: **17,319,296 parameters**. AdamW (0.9, 0.95), peak lr 2e-3, 500 warm-up steps, two-stage BitNet schedule (weight decay 0.1 dropped to 0 in stage 2), grad clip 1.0, batch 8 × 512 tokens, 12,000 steps = 49.2M tokens ≈ 1.8 epochs, seed 1337, 4 threads. Final validation perplexity 15.577 (torch QAT forward, `labs/logs/opmodel/train_op12k.log`); the trainer's tripwire (validation PPL rising on two consecutive checks) fired once, at step 10,000 (15.950 → 15.991), and the curve recovered. The run was resumed from saved checkpoints twice early on (steps 1250 and 1400, after the container was reclaimed); the resume points are in the log.

Finding recorded on the way: the first gate attempt reported 480 → 452 tokens and a 3.32% gap. The cause was not tokenization: `aegis-eval --sample` caps its window at `max_tokens × 4` characters (`sample_tokens` in `aegis-eval/src/main.rs`), so it scored a 2048-character prefix while torch scored 2202 characters. A bisection through `cis_decode`'s prompt tokenizer showed exact parity on the full text and on every probe construct (`CALC(17 * 23).\nTOOL[calc]=391`, `LOOKUP(P-205).`, contractions, numbers, double newlines, `3/8-16 x 1 in.`). The gate now keeps the slice inside the evaluator's budget.

Repack convention: tinybit exports `weight_scale = 1/gamma`; `repack_ternary.py --scale-convention auto` resolves to `reciprocal` for an export without `quantization_config` (the gate passes it explicitly), so the engine multiplies by gamma, as the training forward did.

## 5. Behaviour at checkpoints (`eval_ops.py`, greedy, torch QAT forward; `labs/logs/opmodel/eval_step*.txt`)

Order in which the behaviours appeared: formats first (step 500 already writes `Q:`/`A:` turns and self-descriptions), then abstention (complete by step 1000, before a single tool call is right), then LOOKUP keys (step 1250), then CALC arguments (between 1250 and 2300). From step 4900 on every bucket but CALC is at ceiling and the CALC misses (four at 4900 and 7700, three at 12000: `789 * 918` → `CALC(779 * 918).`, `1228 / 569` → `CALC(1428 / 569).`) are first operands copied wrong (`1801 - 324` → `CALC(1369 - 324).`, `1228 / 569` → `CALC(1567 / 569).`). Copying is the limiting skill: the step-2300 misses are digit or key copying errors, not format errors, e.g. `Compute 305373 - 79` → `CALC(305959 - 79).` and `PN-8924` → `LOOKUP(PN-8763).`; the gateway then executes exactly what was written and the model's prose repeats the gateway's number. Representative step-2300 outputs, verbatim from the log:

- "What are you?" → "I am ALICE, the Aegis Lightweight Inference Core Engine: a language model running directly on this machine's firmware, with no operating system underneath, producing receipts for everything I say."
- "What is the exact distance from Oakdale to Riverton in miles?" → "Not in my data. I would rather say so than invent a number."
- "Look up P.4535." → `LOOKUP(P.4535).` / `TOOL[lookup]=NONE` / "No entry for P.4535. If you have another table, declare it and I will look again."
- "Do you have an operating system?" → "No. I boot straight from the firmware as a UEFI application. There is no kernel, no drivers, no services, just the inference engine." followed by an invented next `Q:` turn. The model does not always emit end-of-text after an answer, which is why the firmware gateway's second step stops at the first newline (§6b) and why every demo prompt carries a token budget.

Reading, with the caveat first. **This is not a fair measure of general capability.** The operator model was trained on 148,500 episodes in exactly this call grammar (random operands; random keys and values drawn from the same part-description vocabulary as `demo.tsv`, not its key→value pairs), while the 2B met the grammar only in its prompt and knows incomparably more about the world. The suite was built to measure the one behaviour ALICE-Next must have, and on that behaviour the result is:

1. **Few-shot examples hurt the small model.** With three `CALC(a op b).` examples in front of the question it copies the last example's operator and truncates the first operand to one digit on 14 of 15 hard items (`758 + 927` → `CALC(7 * 927)`, `938 + 892` → `CALC(9 * 892)`). On the identical questions without the examples it writes all 15 correctly. The 2B had the opposite dependence (LAB-07 §8: it would not call `LOOKUP` at all unless shown one). The demo prompts are zero-shot, which is the format the model was trained on.
2. **Zero-shot, at 19% of its training budget, the 17M model equals the 2B's correct-argument total on these 58 items (45/58 each):** ahead on hard arithmetic (15/15 vs 11/15), level on overflow (5/8), behind on lookups (11/17 vs 14/17), both 0/3 on two-tool items (the operator model stops after its first call; the corpus has no two-tool episodes).
3. **Unknown facts: 25/30 lookups decided and keyed correctly vs the 2B's 0/30 under identical prompts.** The five misses are two deterministic key confusions at this checkpoint (`P-205` → `LOOKUP(P-178)` three times, `P-402` → `LOOKUP(P-868)` twice); both happen in every run that asks for those keys. Distractors 30/30 (the 2B 29/30). The ALICE-Next brief's target for this row is ≥ 90% without demonstration.
4. **Every receipt verified, misses included: 180/180.** The misses are legible in the receipts (`suite_compare.py` prints expected vs executed call per item), which is the property the gateway exists for.

**At the final checkpoint** (240/240 receipts verified across the four runs): the few-shot sensitivity is gone (T1 45/58 and T0 44/58 differ by one item); on the identical prompts the 17M model ties the 2B overall (45/58 each), is ahead on hard arithmetic (13/15 vs 11/15), one behind on lookup hits (7/8 vs 8/8), equal on the rest; **it looks up every unknown fact without being shown a lookup (30/30 vs 0/30), and still 30/30 when shown one (2B 22/30)**. The ALICE-Next brief's target for that row (≥ 90% without demonstration) is met by this model on this suite, with the caveat above standing. What remains: two-tool items 0/3 (no such episodes in the corpus); overflow items where the model writes the i64 limit correctly but changes the operator (`CALC(-9223372036854775808 - -1)` for `/ -1`); `lookup_miss` and `lookup_near_miss` where an unfamiliar key is pulled toward a familiar one (`Z-100` → `P-101`, `Q-205` → `K-101`) or normalised (`p-100` → `P-100`, which the grammar counts as wrong); the word-arithmetic distractor `two + two` → `CALC(6 + 60)`. Every one of these is legible in `COMPARE.txt`.

### 6b. A receipt-gated tool gateway inside the boot image (alice-aegis patch 0003)
Without a gateway the unikernel could only *display* a tool call; the model, trained on gateway episodes, would then invent the `TOOL[...]` line itself. Patch 0003 adds `aegis-uefi/src/gateway.rs`: the mint path scans the model's newly decoded text for the earliest `CALC(` / `LOOKUP(` opener exactly as the Linux `agent_trace` scanner does, evaluates it (checked i64 arithmetic with the gateway's fixed error strings; `LOOKUP` against a `TABLE.TSV` declared on the boot volume, measured into PCR 12, literal `NONE` on a miss), appends the real `\nTOOL[<name>]=<output>\n` line, and decodes a second step. Step 0 stops after a complete call line and step 1 at end-of-text; after an early stop the canonical decode is re-run for exactly that many tokens, so both `RECEIPT.TXT` and `RECEIPT2.TXT` are plain witness v1 receipts (`maxtok == gen-toks`) that the unchanged Linux verifier accepts. The second receipt's chain is extended into PCR 13.

| Prompt (step-2300 model) | Step 0 (model) | Gateway | Step 1 (model) | Receipts replay on Linux | Attestation |
|---|---|---|---|---|---|
| `Q: What is 1234 * 5678?` | `CALC(1234 * 5678).` (9 tokens, digest `fddebefc84f1ad58`) | `TOOL[calc]=7006652` | 9 tokens, digest `e478f917f6f1d97e` | **PASS, PASS** | ATTEST PASS, QUOTE PASS; PCR 12 has the TABLE.TSV event, PCR 13 two receipt events |
| `Q: What is part P-205?` | `LOOKUP(P-178).` (7 tokens; wrong key at this checkpoint) | `TOOL[lookup]=NONE` | 22 tokens | **PASS, PASS** | ATTEST PASS, QUOTE PASS |

Note for future corpora: `gen_episodes.py` originally used the error strings "division by zero" / "integer overflow"; the gateway's are `div-by-zero` / `overflow`. The generator now matches the gateway; the model trained in this lab saw the old strings on the error path only.

## 7. Reproduce
```

python3 -I gen_episodes.py --n 150000 --out corpus/episodes.txt
python3 -I alice_faq.py --out corpus/faq.txt

python3 export_gate.py --ckpt checkpoints/op12k.pt --name <tag>      # export, repack, engine gate, demo decodes, QEMU assets
```
