# LAB-08 — Training the demo operator model for ALICE on CPU (op12k)

**Date:** 2026-10-07 · **Host:** this 4-vCPU cloud VM, no GPU (env=vm) · **Status:** training in progress; sections 4-6 are filled in as checkpoints land.
**Rule A:** no throughput, tokens/s or wall-clock figure in this note is a product number; training speed is mentioned only to explain the budget. **Rule B:** every digest, count and rate below is copied from a file under `labs/logs/opmodel/` or `model/demo-operator/`.

## 1. Why
The QEMU demo (LAB-04, LAB-06) boots the M7 gate model, a 14M-parameter ternary model trained on children's stories; its receipts are exact but its answers are "Once upon a time, there was a little girl named Lily". The request was a demo model that gives much more impressive responses. A fine-tune of the 2B needs a GPU this machine does not have (the Kaggle notebook in `model/kaggle/` is that path). What *can* be trained here in a working day is a small ternary **operator model** whose value is behaviour, not trivia: it answers in ALICE's voice, delegates arithmetic to `CALC`, reads declared tables with `LOOKUP`, refuses to invent records, and describes the machine it runs on. Everything it learns about tools is produced by an exact oracle in the gateway's own text format, so the training signal cannot be wrong.

SmolTalk was considered and excluded: its core subset is generated by a Llama model, which the ledger (`model/03`) keeps out of the shipping path. Tokenizer: byte-level BPE, 12,288 ids, `<|endoftext|>` pinned to id 0, trained on 60 MB of the mix (`tokenizer_op12k.json`). Packed data: 26,800,615 tokens train, 264,582 valid (≈ 4.2 bytes/token). Validation holds out 1% of every source.

## 3. Model and recipe (`model/demo-operator/op12k.json`)
Llama-family decoder matching the engine: RMSNorm, RoPE θ=10000, GQA 6 heads / 2 kv heads, SwiGLU, BitNet SubLN, tied embeddings, all 7 projections `BitLinear` ternary QAT with per-token int8 activations (tinybit `model.py`, engine-parity contract in its README). hidden 384, intermediate 1024, 8 layers, vocab 12,288, ctx 512: **17,319,296 parameters**. AdamW (0.9, 0.95), peak lr 2e-3, 500 warm-up steps, two-stage BitNet schedule (weight decay 0.1 dropped to 0 in stage 2), grad clip 1.0, batch 8 × 512 tokens, 12,000 steps = 49.2M tokens ≈ 1.8 epochs, seed 1337, 4 threads.

## 4. Round-trip gate (train → export → repack → engine)
Gate script `model/demo-operator/export_gate.py`, adapted from tinybit's `roundtrip_gate.py`: the held-out slice deliberately concatenates an episode document (Q:/A:/TOOL lines), an ALICE Q/A and prose, so tokenizer parity is tested on the text shapes the demo uses.

| Checkpoint | ours → engine tokens | torch QAT PPL | engine PPL | rel diff | verdict | log |
|---|---|---|---|---|---|---|
| step 250 | 448 → 448 (parity) | 176.6865 | 177.2790 | 0.33% (tol 3%) | PASS | `labs/logs/opmodel/gate_step250/` |

Finding recorded on the way: the first gate attempt reported 480 → 452 tokens and a 3.32% gap. The cause was not tokenization: `aegis-eval --sample` caps its window at `max_tokens × 4` characters (`sample_tokens` in `aegis-eval/src/main.rs`), so it scored a 2048-character prefix while torch scored 2202 characters. A bisection through `cis_decode`'s prompt tokenizer showed exact parity on the full text and on every probe construct (`CALC(17 * 23).\nTOOL[calc]=391`, `LOOKUP(P-205).`, contractions, numbers, double newlines, `3/8-16 x 1 in.`). The gate now keeps the slice inside the evaluator's budget.

Repack convention: tinybit exports `weight_scale = 1/gamma`; `repack_ternary.py --scale-convention auto` resolves to `reciprocal` for an export without `quantization_config` (the gate passes it explicitly), so the engine multiplies by gamma, as the training forward did.

## 7. Reproduce
```
cd model/demo-operator
python3 -I gen_episodes.py --n 150000 --out corpus/episodes.txt
python3 -I alice_faq.py --out corpus/faq.txt
python3 -I build_corpus.py --oasst <oasst2_all.messages.jsonl.gz> --cosmo <cosmopedia-v2 shard 0> --episodes corpus/episodes.txt --faq corpus/faq.txt --out-dir corpus --cosmo-bytes 90000000 --oasst-repeat 2 --faq-repeat 8
python3 <tinybit>/train_tokenizer.py --input corpus/train.txt --vocab-size 12288 --max-bytes 60000000 --out tokenizer_op12k.json
python3 <tinybit>/prepare_data.py --input corpus/train.txt --tokenizer tokenizer_op12k.json --out train_op12k.bin   # and valid
python3 <tinybit>/train.py --config op12k.json
python3 export_gate.py --ckpt checkpoints/op12k.pt --name <tag>      # export, repack, engine gate, demo decodes, QEMU assets
```
